# Handoff 2026-11-05: threads and branches (M2)

## What changed

- **Thread sidebar.** All threads, newest first, with their branches nested under the thread they came from. **New thread** opens an empty thread; it is created when its first question is sent, so no empty threads pile up. On narrow windows the sidebar opens from the ☰ button.
- **Ask in a branch.** Selecting text in any finished message (question or answer) shows **Ask in a branch**, which replaces the M0 "Pin passage" spike. The branch opens with the passage at the top and is created on its first question, together with the question, in one request (`POST /api/threads/:id/branches`).
- **Exact origin.** The server stores the anchor itself: the message revision, the offsets into its raw Markdown, and the quote with 32 characters of context either side (W3C selectors). It recomputes the quote from the stored text; the client only sends offsets.
- **Marks where branches left.** In the parent thread, each origin passage is underlined, and a chip under the message opens the branch.
- **Back.** The branch's **← Back** returns to the parent at the exact passage, scrolled into view and highlighted. The URL is `#/t/<parent>/from/<branch>`, so the browser's own Back and Forward also work. Each return is logged (`branch.returned`) for the brief's §11 measures. Cancelling a branch before asking also returns to the passage.
- **Context for branches.** A branch sends the visible conversation of every ancestor up to the message the passage came from (later parent messages are left out), then the branch's own turns, then the question with the passage quoted in front of it. The passage goes with the question rather than earlier, so the shared prefix stays identical and DeepSeek's prompt cache keeps working. The manifest marks these parts as `inherited` and `origin`.
- **Nesting.** Branches can branch; the origin card shows the whole path as breadcrumbs.
- **Storage.** Migration `002_branches.sql` adds an `anchor` table and `thread.parent_thread_id` and `thread.origin_anchor_id`. Existing notebooks upgrade in place on the next start.
